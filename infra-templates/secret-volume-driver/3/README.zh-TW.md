# PastureStack 機密資料磁碟區

此基礎架構範本會在每台符合條件的受管主機上安裝一個主機本機 Docker
磁碟區驅動程式。相容控制平面會為每個已核准的機密資料磁碟區提供不透明
授權權杖。驅動程式只會取得對應的加密紀錄、驗證簽章、使用主機身分
金鑰解密，再透過隔離的記憶體檔案系統向目標工作負載提供唯讀檔案。

## 安全性界線

服務使用 `ghcr.io/pasturestack/secrets-flexvolume-plugin:v0.1.1`。
商店與使用者介面只顯示語意化版本標籤，不顯示映像摘要。

容器：

- 先移除所有 Linux Capability，再加入建立及移除隔離 `tmpfs` 所需
  的 `SYS_ADMIN`、套用工作負載要求數字擁有者所需的 `CHOWN`，以及
  變更擁有者後鎖定最終模式所需的 `FOWNER`；
- 停用 Docker 預設 AppArmor 設定檔，因為該通用設定會阻擋必要的
  `tmpfs` 掛載系統呼叫；容器仍不是特權容器、只保留上述三個
  Capability、啟用 `no-new-privileges`，並受下列其他控制限制；
- 使用唯讀根檔案系統與有容量上限、不可執行的暫存目錄；
- 不使用特權模式、主機網路、主機 PID 或容器引擎 Socket；
- 只透過一個唯讀綁定掛載讀取主機身分金鑰；以及
- 只寫入 Docker 外掛 Socket 與專用共用磁碟區根目錄。

機密資料檔案只接受安全的相對路徑、有範圍限制的 UID/GID，以及唯讀
模式。健康狀態回應與日誌均排除資料值、權杖、登入資訊、身分金鑰、
檔名及加密封裝。最後一個工作負載使用者釋放磁碟區後，磁碟區會卸載
並清除。

## 工作負載使用方式

請先透過相容控制平面建立機密資料，再從工作負載的「機密資料」區段
選取。控制平面會建立必要磁碟區並提供授權權杖；管理者不需把機密資料
放入 Compose、商店答案或命令列參數。

驅動程式註冊名稱為 `pasturestack-secret-volume`。健康狀態故障不會
自動重建驅動程式容器，以免重新啟動循環干擾正在使用的掛載。

原始碼、操作方式、安全性、授權及發布證據請參閱
[PastureStack 機密資料磁碟區驅動程式儲存庫](https://github.com/PastureStack/secrets-flexvolume-plugin)。

PastureStack 是獨立的社群計畫，目的在保存、稽核與現代化 Rancher
1.6 生態系；本計畫與 Rancher Labs 或 SUSE 無隸屬或背書關係。
